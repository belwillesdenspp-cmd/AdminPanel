# Руководство пользователя GLPI Cleaner

Документ для человека, который раньше **не** настраивал эту программу.  
Если какой-то термин непонятен — смотрите [раздел 9. Глоссарий](#раздел-9-глоссарий).

---

## Введение

### Что делает программа

**GLPI Cleaner** подключается к порталу заявок GLPI (Service Desk) и по вашим правилам находит старые заявки (например, закрытые больше года назад), показывает список и при необходимости удаляет их — сразу или по расписанию.

### Кому она нужна

Сотрудникам, которые обслуживают GLPI и хотят регулярно чистить архив закрытых заявок без ручного поиска в веб-интерфейсе.

### Что программа НЕ делает

- Не создаёт и не редактирует заявки.
- Не меняет права пользователей в GLPI.
- Не делает резервную копию базы данных — это нужно сделать отдельно перед первым массовым удалением.
- Не «угадывает» правила за вас: удаляет только то, что вы задали в настройках.

### Схема работы

```
GLPI (портал заявок)
        ↓
  программа читает список по фильтру
        ↓
  Dry-Run: показывает, что попало под правила
        ↓
  при реальном запуске: удаление (в корзину или навсегда)
```

## Раздел 1. Что понадобится перед началом

1. **Доступ к GLPI под учётной записью с правами администратора** (или с правом на API и удаление заявок).
2. **Адрес портала** — например `https://support.willesden.by` (точный адрес даст ваш администратор).
3. **App-Token и User-Token** — это «пароли для программы», не для входа в браузер. Как получить — [приложение Б](#приложение-б-как-получить-токены-в-glpi).
4. **Компьютер:**
   - Windows 10/11 или Windows Server — удобно с окном программы (`.exe`);
   - Linux-сервер — без окна, через службу или cron;
   - Docker — если у вас уже есть Docker.
5. **Права на удаление заявок** у того пользователя GLPI, чей User-Token вы используете. Без этих прав программа подключится, но удалить ничего не сможет.

## Раздел 2. Установка на Windows (пошагово)

### Вариант А. Есть готовый `.exe` (проще)

1. Скопируйте папку `glpi_cleaner` (или `dist` с файлами) на компьютер, например в  
   `C:\Programs\glpi_cleaner\`.
2. Убедитесь, что рядом с `GLPI_Cleaner.exe` лежит файл `config.json`.
3. Запустите `GLPI_Cleaner.exe` двойным щелчком.

**Что вы должны увидеть:** окно с четырьмя вкладками: «Подключение», «Правила удаления», «Расписание», «Журнал».

Если Windows Defender или антивирус спросит разрешение — разрешите запуск для этой папки (файл собран вами/вашей ИТ-службой).

### Вариант Б. Запуск из исходников (если нет `.exe`)

1. Установите **Python 3.10 или новее** с [python.org](https://www.python.org/downloads/).  
   На экране установки поставьте галочку **«Add python.exe to PATH»**.
2. Откройте командную строку: `Win + R` → `cmd` → Enter.
3. Перейдите в папку проекта:

```bat
cd /d C:\Programs\glpi_cleaner
```

(подставьте свой путь)

4. Установите библиотеки:

```bat
python -m pip install -r requirements.txt
```

5. Запустите окно программы:

```bat
python main.py
```

**Что вы должны увидеть:** то же окно с четырьмя вкладками.

Для сервера без окна:

```bat
python cli.py --once
```

## Раздел 3. Первоначальная настройка

### 3.1. Вкладка «Подключение»

| Поле | Что вводить | Пример |
|------|-------------|--------|
| URL API GLPI | Адрес портала + `/apirest.php` | `https://support.willesden.by/apirest.php` |
| App-Token | Токен приложения из настроек API | длинная строка символов |
| User-Token | Токен вашего профиля | длинная строка символов |
| Таймаут | Сколько секунд ждать ответа | `120` |
| Проверять SSL | Оставьте галочку, если сертификат сайта нормальный. Снимите, если IT сказали, что сертификат «самоподписанный» и браузер ругается | — |

1. Заполните поля.
2. Нажмите **«Проверить подключение»**.
3. Нажмите **«Сохранить»**.

**Что вы должны увидеть при успехе:**  
текст вроде `Подключение успешно. Версия GLPI: 10.0.x` (номер может отличаться).

**Если ошибка** — см. [раздел 7](#раздел-7-частые-проблемы-и-решения) и [FAQ.md](FAQ.md).

### 3.2. Вкладка «Правила удаления»

1. **«Удалять заявки старше»** — число и единица:
   - `1` + `years` = старше 1 года;
   - `6` + `months` = старше 6 месяцев;
   - `90` + `days` = старше 90 дней.
2. **Поле даты:**
   - `date` — дата **открытия** заявки (обычно то, что нужно);
   - `date_mod` — дата последнего изменения.
3. **Статусы:** по умолчанию `5,6` — «Решена» и «Закрыта». Не удаляйте «новые» и «в работе», если не уверены.
4. **Dry-Run** — галочка «только предпросмотр». **Всегда начинайте с неё включённой.** Программа покажет список, но **ничего не удалит**.
5. **Force purge** — если включить, заявки удаляются **навсегда** (не в корзину). По умолчанию выключено — безопаснее.

Нажмите **«Предпросмотр (Dry-Run)»**.

**Что вы должны увидеть:** таблицу с номерами заявок, статусом и датой открытия; внизу — сколько нашлось. Вкладка «Журнал» тоже заполнится строками.

### 3.3. Вкладка «Расписание»

1. Поставьте галочку **«Включить планировщик»**, если нужен автозапуск.
2. Периодичность: `daily` = каждый день.
3. Время: `00:00` — в полночь (время компьютера, где запущена программа).
4. Нажмите **«Сохранить»**, затем **«Запустить планировщик»**.

**Что вы должны увидеть:** строка `Следующий запуск: 17.10.2026 00:00` (дата будет вашей следующей по календарю).

Для разового запуска вне расписания — **«Запустить сейчас»** (используются правила из вкладки «Правила», включая Dry-Run!).

### 3.4. Сохранение конфигурации

- Файл **`config.json`** лежит **в той же папке**, что и программа.
- При нажатии «Сохранить» программа перезаписывает этот файл.
- Его можно открыть блокнотом и править вручную (см. [приложение В](#приложение-в-пример-configjson)).
- Если файл удалить — при следующем запуске создастся новый с безопасными значениями по умолчанию (Dry-Run включён, токены пустые).

## Раздел 4. Первый запуск (безопасно)

1. Включите галочку **Dry-Run**.
2. Нажмите **«Предпросмотр (Dry-Run)»**.
3. Посмотрите, **сколько** заявок в таблице и в сообщении внизу.
4. Откройте вкладку **«Журнал»** — там должны быть строки без паролей/токенов.
5. Убедитесь, что в списке нет заявок, которые ещё нужны.
6. Сделайте **резервную копию базы GLPI** (попросите администратора БД).
7. Только после этого:
   - снимите Dry-Run;
   - решите, нужен ли Force purge (обычно **нет** — достаточно корзины);
   - нажмите **«Удалить сейчас»** и подтвердите два раза.

**ПРЕДУПРЕЖДЕНИЕ:** при включённом Force purge восстановление из корзины GLPI невозможно. Откат — только из резервной копии БД.

## Раздел 4а. Журнал удалённых и выгрузка Excel (v1.1)

### Вкладка «Удалённые»
- После реального удаления (не Dry-Run) заявка попадает в журнал: № GLPI, дата удаления, статус, тема, сектор, инициатор.
- Поиск: № заявки, диапазон дат удаления, сектор, инициатор, тема.
- Таблица с постраничным выводом и счётчиком.
- «Выгрузить Excel (фильтр)» — только найденные записи (нужен путь на вкладке «Выгрузка»).

### Вкладка «Выгрузка»
- Путь сохранения (локальный или `\\server\share\...`).
- Автовыгрузка: вкл/выкл, время, объём (все / за N дней).
- Папки по датам удаления: `<путь>/<YYYY-MM-DD>/deleted_tickets_….xlsx` (формат папки и имени — в настройках).
- Для сети: домен, логин, пароль (пароль хранится зашифрованным, в лог не пишется).
- «Проверить доступ» / «Выгрузить сейчас».

Файл журнала по умолчанию: `data/deleted_tickets.jsonl` рядом с программой (ключ `journal.path` в config.json).

## Раздел 5. Ежедневная работа

1. **Проверка работы** — вкладка «Журнал» или файл `logs\glpi_cleaner.log`.
2. **Что удалилось за сутки** — ищите в логе строки с «Удалено пакетом» / «Готово:».
3. **Временно остановить планировщик в окне** — вкладка «Расписание» → «Остановить планировщик в окне».
4. **Снова включить в окне** — «Запустить планировщик в окне» (окно при этом нужно не закрывать).
5. **Разово вне расписания** — «Запустить сейчас» или «Удалить сейчас» / «Предпросмотр».

На сервере без окна смотрите логи в папке `logs` и статус службы (см. раздел 6).

### 5.1. Работа в фоне (рекомендуется для ежедневной очистки)

Программа **умеет работать в фоне** — без открытого окна. Есть три удобных способа.

#### Способ А. Кнопка «Запустить в фоне» (самый простой из окна)

1. Настройте подключение и правила (сначала Dry-Run).
2. На вкладке **«Расписание»** задайте периодичность и время, нажмите **«Сохранить»**.
3. Нажмите **«Запустить в фоне»**.
4. Убедитесь, что статус стал: `Фон: работает (PID …)`.
5. Окно можно **закрыть** — очистка по расписанию продолжится.
6. Чтобы остановить: снова откройте программу → **«Остановить фон»**.

**Что нужно:** рядом с `GLPI_Cleaner.exe` должен лежать файл **`glpi-cleaner-cli.exe`** (оба лежат в папке `dist` после сборки).

**Что вы должны увидеть в логе** (`logs\glpi_cleaner.log`): строки о запуске демона и о следующих прогонах очистки.

#### Способ Б. Свернуть в трей (окно скрыто, процесс тот же)

1. На вкладке «Расписание» нажмите **«Свернуть в трей»**  
   (или закройте окно, если включена галочка «При закрытии окна — сворачивать в трей»).
2. В правом нижнем углу Windows появится значок GLPI Cleaner.
3. Правый щелчок по значку → «Открыть окно» или «Выход».

Этот способ удобен, пока вы работаете за этим ПК. Для сервера лучше способ А или служба (раздел 6).

#### Способ В. Командная строка / служба

```bat
glpi-cleaner-cli.exe --daemon
```

Или служба NSSM / Task Scheduler / Linux systemd — см. раздел 6.

**Важно:** при фоновом запуске используются настройки из `config.json` (в том числе Dry-Run). Перед включением фона на «боевое» удаление снимите Dry-Run и сохраните настройки.

## Раздел 6. Перенос на другой ПК / сервер

### 6.1. Другой Windows ПК

1. Скопируйте **всю** папку (`.exe`, `config.json`, `logs` по желанию).
2. Проверьте, что `config.json` на месте и токены не «потерялись».
3. Запустите `GLPI_Cleaner.exe`.

Переустанавливать Python не нужно, если пользуетесь `.exe`.

### 6.2. Windows Server как служба (NSSM)

1. Скачайте [NSSM](https://nssm.cc/download) и распакуйте.
2. Откройте командную строку **от имени администратора**.
3. Укажите путь к CLI:

```bat
nssm install GLPICleaner "C:\Programs\glpi_cleaner\glpi-cleaner-cli.exe" "--daemon"
```

4. В NSSM на вкладке **I/O** укажите файлы для stdout/stderr в папку `logs`, если нужно.
5. Запустите:

```bat
nssm start GLPICleaner
```

6. Проверка: `Win + R` → `services.msc` → служба **GLPICleaner** — состояние «Работает».
7. Логи: `C:\Programs\glpi_cleaner\logs\glpi_cleaner.log`.

### 6.3. Linux Server

Подробности: [INSTALL_LINUX.md](INSTALL_LINUX.md). Кратко:

```bash
sudo mkdir -p /opt/glpi-cleaner
sudo cp -r * /opt/glpi-cleaner/
sudo useradd -r -s /usr/sbin/nologin glpi-cleaner || true
sudo chown -R glpi-cleaner:glpi-cleaner /opt/glpi-cleaner
sudo cp /opt/glpi-cleaner/glpi-cleaner.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now glpi-cleaner
sudo systemctl status glpi-cleaner
```

Логи: `/opt/glpi-cleaner/logs/`.

### 6.4. Docker

См. [INSTALL_DOCKER.md](INSTALL_DOCKER.md).

```bash
docker compose up -d --build
docker logs -f glpi-cleaner
```

### 6.5. Планировщик ОС (без службы программы)

**Windows Task Scheduler**

1. Планировщик заданий → Создать задачу.
2. Триггер: ежедневно в нужное время.
3. Действие: запуск программы  
   `C:\Programs\glpi_cleaner\glpi-cleaner-cli.exe`  
   аргументы: `--once`
4. Рабочая папка: `C:\Programs\glpi_cleaner`.

**Linux crontab**

```cron
0 0 * * * /opt/glpi-cleaner/glpi-cleaner-cli --once >> /opt/glpi-cleaner/logs/cron.log 2>&1
```

В `config.json` перед этим выставьте `dry_run: false`, если нужно реальное удаление (сначала проверьте Dry-Run вручную).

## Раздел 7. Частые проблемы и решения

| Симптом | Причина | Решение |
|---------|---------|---------|
| Ошибка 401 | Неверный App-Token или User-Token | Пересоздайте токены в GLPI, вставьте заново, «Сохранить» |
| Ошибка соединения / timeout | Неверный URL, сеть, VPN, файрвол | Проверьте URL с `/apirest.php`, доступ с этого ПК к порталу |
| SSL-ошибка / certificate verify failed | Самоподписанный сертификат | Снимите галочку «Проверять SSL» и сохраните |
| Не удаляется ни одна заявка | Включён Dry-Run | Снимите Dry-Run **после** успешного предпросмотра |
| Удаляется слишком много | Слишком «мягкий» возраст или лишние статусы | Остановите планировщик, уменьшите период, снова Dry-Run |
| Служба не запускается | Неверный путь в NSSM/systemd | Проверьте путь к `.exe`/бинарнику и `WorkingDirectory` |
| Программа сразу закрывается | Антивирус / нет прав на папку | Запуск от администратора; исключение в антивирусе |
| Пустая таблица при предпросмотре | Нет заявок старше порога с нужным статусом | Увеличьте период или проверьте статусы в GLPI |
| 404 при удалении | Заявка уже удалена | Нормально при повторном прогоне; смотрите лог |

## Раздел 8. Безопасность и важные предупреждения

1. **Токены = пароль.** Не отправляйте их в чат и не кладите в публичный git.
2. **Не включайте Force purge**, пока не уверены и нет бэкапа БД.
3. **Всегда начинайте с Dry-Run.**
4. Перед первым массовым удалением — **резервная копия БД GLPI**.
5. Храните `config.json` в папке с ограниченным доступом.
6. Регулярно читайте `logs/glpi_cleaner.log`.

## Раздел 9. Глоссарий

| Термин | Простыми словами |
|--------|------------------|
| API | Способ, которым программы общаются друг с другом без браузера |
| Токен | Аналог пароля для программы |
| Тикет / заявка | Обращение пользователя в поддержку |
| Dry-Run | «Примерка»: показывает, что будет удалено, но ничего не удаляет |
| Планировщик | Запуск программы в заданное время автоматически |
| Headless | Работа без графического окна (на сервере) |
| Daemon / служба | Программа, которая постоянно работает в фоне |
| Трей | Область у часов Windows; значок скрытого окна |
| «Запустить в фоне» | Кнопка: отдельный процесс очистки без окна |
| Force purge | Удаление навсегда, не в корзину |
| config.json | Файл настроек рядом с программой |

## Приложение Б. Как получить токены в GLPI

Текстовая схема (названия пунктов меню могут чуть отличаться в вашей версии GLPI):

```
Вход в GLPI как администратор
        ↓
Настройки → Общие → API
        ↓
Включить API (если выключен) → Сохранить
        ↓
Скопировать App-Token (ключ приложения / клиента API)
        ↓
Мой профиль (правый верх / пользователь)
        ↓
Ключ API / Remote access key → Сгенерировать
        ↓
Скопировать User-Token
        ↓
Вставить оба значения во вкладку «Подключение» программы → Сохранить
```

1. Войдите в GLPI как администратор.
2. Откройте **Настройки → Общие → API**.
3. Включите API и сохраните. Создайте/выберите клиент API, скопируйте **App-Token**.
4. Откройте свой профиль → раздел ключа API → сгенерируйте **User-Token**.
5. Вставьте оба значения в программу и нажмите «Проверить подключение».

## Приложение В. Пример config.json

```json
{
  "glpi": {
    "url": "https://support.willesden.by/apirest.php",
    "app_token": "",
    "user_token": "",
    "verify_ssl": true,
    "timeout": 120
  },
  "deletion": {
    "max_age_value": 1,
    "max_age_unit": "years",
    "date_field": "date",
    "statuses": [5, 6],
    "force_purge": false,
    "dry_run": true,
    "batch_size": 50,
    "page_size": 1000
  },
  "schedule": {
    "enabled": false,
    "mode": "daily",
    "time": "00:00",
    "interval_hours": 24
  },
  "logging": {
    "level": "INFO",
    "max_bytes": 5000000,
    "backup_count": 5
  }
}
```

Пояснения:

| Поле | Смысл |
|------|--------|
| `max_age_value` | На сколько «старше» (число) |
| `max_age_unit` | Единица: `days` / `months` / `years` |
| `date_field` | `date` = открытие, `date_mod` = изменение |
| `statuses` | Коды статусов GLPI: 5 решена, 6 закрыта |
| `force_purge` | `true` = навсегда, `false` = в корзину |
| `dry_run` | `true` = только показать, не удалять |
| `schedule.enabled` | Включён ли автозапуск внутри программы |
| `verify_ssl` | Проверять ли сертификат HTTPS |

## Пример проверки API вручную (curl)

Подставьте свои URL и токены:

```bash
# 1. Сессия
curl -k -s -H "App-Token: ВАШ_APP_TOKEN" \
  -H "Authorization: user_token ВАШ_USER_TOKEN" \
  "https://support.willesden.by/apirest.php/initSession"

# Ответ содержит session_token — скопируйте его

# 2. Поиск (пример: закрытые, дата открытия раньше порога)
curl -k -s -H "App-Token: ВАШ_APP_TOKEN" \
  -H "Session-Token: ВАШ_SESSION" \
  "https://support.willesden.by/apirest.php/search/Ticket?criteria[0][field]=12&criteria[0][searchtype]=equals&criteria[0][value]=6&range=0-0"

# 3. Закрыть сессию
curl -k -s -H "App-Token: ВАШ_APP_TOKEN" \
  -H "Session-Token: ВАШ_SESSION" \
  "https://support.willesden.by/apirest.php/killSession"
```

Флаг `-k` — только если сертификат самоподписанный (как снятие галочки SSL в программе).
