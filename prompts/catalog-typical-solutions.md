# Каталог решений типовых заявок УИТ

Источники:
- Классификация: `Классификация типовых заявок — по секторам (1).md` (85 категорий, GLPI, 13.08.2026)
- Детальные инструкции секторов: `СРИСиС.txt`, `НСИ.txt`
- Промпты: `prompt_ai_agent_routing.md`, `prompts/sectors/`

**Назначение:** пошаговые решения для AI-агента и специалистов. Для **СРИСиС**, **НСИ** и **САКПО** — максимальная детализация. Для остальных секторов — кратко из промптов; подробности GLPI KB — в файле классификации.

**Автоназначение L2:** группа GLPI «ОРиСИТ» разводится на **СРиСИС** / **САКПО** / **САиСПС** — см. таблицу ниже и [`prompt_ai_agent_routing.md`](prompt_ai_agent_routing.md) (раздел «Автозакрытие»).

## Маршрутизация L2: разводка группы «ОРиСИТ»

| Группа | Темы | Типовые БЗ id | Робот |
|---|---|---|---|
| **СРиСИС** | цены, ТТН, ЭТТН, партии, документы 1С, акты, резерв | 513, 517, 317, 634, 716, 567, 153, 160, **834** | followup «по БЗ»; **не нажимать** «Пересчитать цены/затраты» |
| **САКПО** | пик-лист, КСО, О!плати, прогрузка касс, Set10, скидка «Хамелеон» | 702, **831**, 425, 77, **832** | followup «по БЗ»; **не прогружать** кассу |
| **САиСПС** | запрет редактирования, колонки LSF, клиент Fusion, права на формы | 512, 35 | followup «по БЗ»; **не выдавать** права |

**Исключение (L1 автоответ):** «прогрузите кассы», «товары грузятся», «очередь Set» → шаблон ожидания **10–15 мин**, **без** назначения на САКПО.

**САКПО и СОКС — обязательные данные в заявке:** для **любой** заявки на **САКПО** или **СОКС** в тексте должны быть **номер телефона** и **номер/адрес торгового объекта (ТО)**. Без них — **неинформативно** ([KB id=278](https://support.willesden.by/front/knowbaseitem.form.php?id=278)), вернуть с запросом. **Исключение:** **бейдж / пароль кассира** — достаточно **ФИО** и **ТО** (в т. ч. из подписи «магазин №…»); **номер кассы не требовать** (роль **кассир** ≠ неисправность **кассы №N**). Для **КСО** дополнительно — **фото ошибки** (см. ниже).

**КСО:** без **фото ошибки**, **телефона** и **ТО** → **неинформативно** (278), не эскалировать.

### Где взять ФИО инициатора, телефон и номер магазина

1. Поле GLPI **«Инициатор запроса»** — для маршрутизации и особых инициаторов.
2. **Подпись обращения** внизу текста заявки (в интерфейсе часто **выделена**), обычно начинается со **«С уважением»**: **ФИО**, должность, подразделение, **внутренний телефон** («вн. тел. …»).
3. **Номер магазина / ТО** — в подписи, в тексте или на скриншотах/таблицах в теле письма (например, «Магазин №152»).

Если данных нет ни в поле «Инициатор», ни в подписи — запросить у пользователя.

### Неинформативные заявки: рассылки и доступы

| Ситуация | Текст закрытия |
|---|---|
| «Добавить во **все рассылки**» (например, «…для зам зав мага») **без названий рассылок** | «Заявка неинформативна: при запросе добавления в рассылки требуется указывать названия рассылок.» |
| «Предоставить **все доступы**» **без перечня** программ, сервисов, папок и прав | «Заявка неинформативна: не соблюдено правило оформления заявок на предоставление доступов.» |

**Рассылки Lotus:** добавление/удаление **получателей** → **САПО**, **без** «К сетевому ресурсу»; **не СПП** ([552473](https://support.willesden.by/front/ticket.form.php?id=552473)); настройка **клиента** → **СПП**.

**Диск X: / M:** — **СПП**, **без** «К сетевому ресурсу»; X: и M: доступны всем пользователям **AD**; **M:** — личный диск; **САПО** — по эскалации от **СПП**. *Пример:* [549454](https://support.willesden.by/front/ticket.form.php?id=549454).

**Скачать файлы по ссылке** (cloud.mail.ru и др.) **в папку на X:\\** — **СПП** (выполнить загрузку на ПК), **не САПО** и **без** «К сетевому ресурсу», если не запрос **нового доступа** к папке. *Пример:* [551663](https://support.willesden.by/front/ticket.form.php?id=551663).

**Планум (Planum):** установка, подключение, настройка на рабочем месте, вход (логин/пароль) → **СПП**, не САПО. **БЗ:** [KB id=840](https://support.willesden.by/front/knowbaseitem.form.php?id=840). *Примеры:* [551682](https://support.willesden.by/front/ticket.form.php?id=551682), [551509](https://support.willesden.by/front/ticket.form.php?id=551509).

**itirsSTAFF (итирсстаф):** доступ → **ОРПОиП** + **«К сетевому ресурсу»**; ярлык `X:\PUBLIC FOLDERS\Ярлыки`; URL https://staff.bwd.by/

**Сетевая папка (путь как в проводнике):** пользователь может указать `Компьютер → CORP (X:) → Departments → … → имя папки` — это **САПО** + **«К сетевому ресурсу»** (не путать с первичным доступом к диску **X:** → **СПП**). *Пример:* [549929](https://support.willesden.by/front/ticket.form.php?id=549929).

| «**Не работает принтер**» без типа, места, модели | **«Заявка неинформативна.»** |

| Тип | Сектор | Где |
|---|---|---|

| То же **А4** в **областных центрах** | **СОКС** | Витебск — **Коваленко Владислав**; Гомель — **Заяц Сергей**; Гродно — **Пышинский Владислав**; Могилёв — **Михнов Юрий** (БВД) / **Потекалов Дмитрий** (БМК); Брест — **СОКС** |
| **URSA / TSC / Godex / Datamax (Датамакс)** (в т. ч. **TSC TX200**), **принтер чеков** (касса, КСО), **товарные** этикетки/ценники (в т. ч. отдел **СП**, уценка) | **СОКС** | Вся география; **не СПП** / **не НСИ** — [549294](https://support.willesden.by/front/ticket.form.php?id=549294), [551481](https://support.willesden.by/front/ticket.form.php?id=551481), [551488](https://support.willesden.by/front/ticket.form.php?id=551488), [551511](https://support.willesden.by/front/ticket.form.php?id=551511) |
| Добавить принтер в Windows / принт-сервер | **СПП** | — |

**Примеры достаточных заявок (→ СОКС):** «На **КСО №5** не работает **принтер чеков**»; «В **непрод. отделе** не работает **принтер этикеток**».

**СПП vs СПОП:** очередь печати, драйвер, «не печатает с ПК» → **СПП**. Полосы/замятие/картридж/ремонт **устройства** (в т. ч. **МФУ** в офисе) → **СПОП** (в контуре географии СПОП) или **СОКС** (область).

## Разведение секторов по смыслу (не по одному слову)

Используй при маршрутизации и при выборе чанка каталога. **Один термин в тексте не решает сектор** — нужен тип работы.

| Тип работы | Сектор | Не путать с |
|---|---|---|
| **Учётный документ** в Fusion/1С: акт, накладная/ТТН, проведение, согласование, правка поля/примечания, **отчёт/сверка в 1С** | **СРИСиС** | НСИ (справочник); СПП (клиент 1С на ПК без учётной задачи) |
| **Справочник:** карточка, ПСЦ, GTIN, **код ТНВЭД в карточке**, стоп-лист, договор как объект НСИ | **НСИ** | СРИСиС (документ/акт/ТТН); «изменения в карточке» при сопровождении **акта** → **СРИСиС** |
| **Кассовое ПО:** зависший чек, касса не завершает продажу, скидка на кассе, пик-лист, SET10 | **САКПО** | СОКС (заставка КСО, терминал **без** зависшего чека) |
| **Банковский терминал / эквайринг** (914, РРН, «терминал не отвечает»), чек **не** завис | **СОКС** | САКПО (зависла **касса/чек** при оплате картой) |
| **Бейдж / пароль / доступ кассиру** | **САКПО + СПП** | САПО (сетевой доступ); номер кассы **не обязателен** |
| **Ремонт офисного А4/МФУ** (дефект печати на бумаге) | **СПОП** / **СОКС** (область) | СПП (очередь Windows) |

Категория GLPI **«ПО → 1С» / «ПО → LS Fusion»** при **учётной** задаче — ориентир на **СРИСиС**, не на пустой сектор.

## Общие правила (вне типовых категорий)

### Прогрузка товаров в кассы

**Прогрузкой товаров в кассы занимается сам магазин (ТО)** — форма **«Рабочий стол / выгрузка пиклиста в оборудование»**. УИТ **не выезжает** для штатной выгрузки; **САКПО** — при **ошибках** прогрузки или неактуальных данных. См. раздел **САКПО** ниже.

### Картинки к товарам / пик-лист (контент)

**Добавление картинок** к товарам или в **пик-лист**, если это **не связано с ошибкой прогрузки пик-листа в оборудование** → **Отдел интернет-продаж** (не УИТ, не НСИ, не САКПО).

**Не путать:** техническая ошибка выгрузки пик-листа на КСО/кассу → **САКПО** — инструкция [KB id=831](https://support.willesden.by/front/knowbaseitem.form.php?id=831).

**Закрытие:** «По данному вопросу обращайтесь в **Отдел интернет-продаж**.»

### Нет заказа на сухой сток

**Сектор (типично):** **СРИСиС** (WMS / Gedemin / заказы склада) — уточнить по контексту.

**Пример заявки:** «Нет заказа на сухой сток, просим помощи».

**Обязательно запросить:** **номер накладной** (если в заявке не указан — вернуть с запросом).

**Закрытие (если данных недостаточно):** «Укажите, пожалуйста, **номер накладной** для разбора.»

### Почта Lotus: письма не приходят / переполнение ящика

**Сектор:** **СПП** (клиент, чистка) + **САПО** (квота, архивирование)

**Пример:** «Не приходят письма от mail.ru и gmail.com, возможно из‑за объёма 20 МБ».

**Лимиты:**
- **Размер одного сообщения** — **20 МБ** (вложения + тело).
- **Объём почтового ящика по умолчанию:** **750 МБ** — **офис**; **500 МБ** — **магазины**.

**При переполнении ящика:** **архивирование** писем или **удаление** старых; **архив тоже имеет ограничения по объёму**.

**Дополнительно запросить:** **конкретные примеры** недошедших писем — **скриншот**, **дата**, отправитель; не принимать только общую формулировку.

**Инструкция:** `Lotus / Инструкция по удалению и архивированию почты.docx`. Увеличение квоты — **САПО**.

### Word: ошибка при открытии файла с сетевой папки (локально открывается)

**Сектор:** **СПП** (+ **САПО**, если нет прав на чтение папки / UNC)

**Признаки:** при открытии `.docx` с **сетевого пути** (`\\server\share\…` или сетевой диск) — *«Ошибка Word при попытке открытия файла»* (проверьте разрешения, память, конвертер резервных копий). **Локальные** файлы на ПК открываются нормально.

**Обязательно запросить:** **полный путь** к файлу (UNC или буква диска); открывается ли **копия** файла на **Рабочем столе**; **Citrix/терминал** или офисный ПК; одна папка или **все** сетевые документы.

**Шаги (СПП):**
1. **Проверка:** скопировать файл на **Рабочий стол** → открыть. Если локально открывается — настраивать Word для **сетевых** путей (не права на папку).
2. **Word** → **Файл** → **Параметры** → **Центр управления безопасностью** → **Параметры…** → **Надёжные расположения**.
3. Включить **«Разрешить надежные расположения в моей сети (не рекомендуется)»**.
4. **Добавить новое расположение** — UNC или буква сетевого диска (например `\\server\share\` или `P:\`), галочка **«Подпапки также являются надежными»** → **ОК** → перезапустить Word.
5. Если не помогло — проверить **длину полного пути** (для Word — **не более 259 символов** с именем файла); при превышении — работать с **копией** в коротком локальном пути.
6. **Права:** если файл **не копируется** и не открывается из проводника — **САПО** (доступ к UNC-папке).
7. Крайний случай: восстановление Office; очистка `%temp%`; отключить **Protected View** для теста (Центр управления безопасностью → **режим просмотра с ограничениями**).

**Закрытие:** «Добавлено надёжное сетевое расположение в Word, проверьте открытие файла с сетевой папки.» / «Файл открывается с локальной копии; для сетевого пути сократите путь или используйте копирование на Рабочий стол.»

**Не путать:** «нет доступа к папке \\…» без Word — заявка на **САПО** (+ «К сетевому ресурсу»).

### Электронный архив / список договоров **Bitrix24**

**Сектор:** **САПО** (обращение в техподдержку)

**Примеры:** не открываются поля **телефона/e-mail** при сохранении договора; **нет клиента в списке** электронного архива — внести контрагента (УНП, реквизиты, PDF). *Заявки:* [551947](https://support.willesden.by/front/ticket.form.php?id=551947) и типовой кейс «не сохраняется договор».

**Решение:** **сервис-запрос на техподдержку** с **реквизитами текстом** в заявке (наименование, УНП, телефон, e-mail и т.д.).

**Не путать:** **внесение договора в Fusion/1С** → **НСИ** (скан договора). CRM **Bitrix24** (компания) → **САПО**, наименование + УНП текстом.

**Маршрутизация:** упоминание **Bitrix24** **не** означает группу GLPI «Битрикс 24» — только **САПО** ± **СПП**.

### Доступ к «Заказы на оплату» / «Бюджеты» (БВД/БМК) **в Lotus**

**Сектор:** **САПО + СПП** | **Категории (по порядку):** **«К сетевому ресурсу»** → после СБ — **«К финансовому ресурсу»**

**Когда:** подключить базы **в клиенте Lotus** (серверы **mo02vlbs02** / **srv-vlds01** — профиль **САПО**).

**Порядок:** **СПП + САПО** → СБ → фин. согласование → **САПО** (права), **СПП** (клиент Lotus) — `GLPI / Инструкция по обработке заявок на предоставление доступа к базам.docx`.

**Обязательно:** ФИО, подразделение, контур **БВД/БМК**, заказы и/или бюджеты.

### Доступ к разделу **Bitrix24 «БП Финансы»**

**Сектор:** **СПП** | **Категории:** **«К финансовому ресурсу»** (финконтур назначает права на ЦФО/ЦФУ и т.п.) | **«К сетевому ресурсу»:** **не ставить** | **САПО:** **не назначать**

**Когда:** доступ к **«БП Финансы»**, **«Заказы на оплату в Bitrix»**, **«Система оплаты»**, БП «Заявка на оплату», «Заявка на налоги», «Заявка на бюджет», «Заявка на доступ к справочникам» и др. (раздел в портале **виден всем** — нужны права внутри контура).

**Инструкция:** https://portal.willesden.by/note/document/15/ (просмотр документа — по запросу на support).

**Не путать:** те же заказы/бюджеты, но **добавление баз в Lotus** — сценарий выше (**с** «К сетевому» и «К финансовому»). **Внесение контрагента** в базу «Заказы на оплату» (скан реквизитов) → **НСИ**.

### Регистрация в программе лояльности (обращение покупателя)

**Сектор:** **вне УИТ** → **отдел маркетинга**

**Пример:** «Связаться с человеком пенсионного возраста, который не может пройти регистрацию по программе лояльности».

**Ответ:** «УИТ **не обрабатывает** такие обращения. Обращайтесь в **отдел маркетинга**.»

### Статус ежедневной загрузки данных КХД (мониторинг DWH)

**Сектор / назначение:** **А2Консалтинг - QlikView** + **Ахримович Кирилл**

**Категория GLPI:** **ПО → QlikView**

**Признаки:** тема **«Статус ежедневной загрузки данных КХД»**; письма **dev-dwhmonitor@willesden.by**; ошибки **ods.*** / **service.load_info**; перегрузка **ODS → DDS → DM**.

**Инициатор:** **Иванов Александр** — **типичен**, **не блокирует** стандартное назначение (исключение из правила «личное внимание СПП»).

**При необходимости:** **+ СРИСиС** — если проблема в источниках данных (Fusion / выгрузки).

**Прочий Qlik / NPrinting:** **СРИСиС + А2Консалтинг** (см. `prompt_ai_agent_routing.md`, рецепт 11).

**Сокращения:** **ФРОВ** = **фрукты и овощи** (частичные инвентаризации — централизованно по запросу руководителя розницы; см. СРИСиС, акты).

### 1. «Расценка ниже себестоимости, обратитесь в офис»

**Признаки:** ошибка при работе с накладными; скрин с реквизитами накладной.

**Шаги:**
1. Открыть накладную из обращения (реквизиты на скрине).
2. Раздел **«Расценка»** → кнопка **«Проверить отриц. ТН»**.
3. Попросить пользователя провести накладную повторно.

**Если не помогло** или проблема не в накладной → **отдел ценообразования (экономисты)**. Такие заявки направлять **в приоритетном порядке**.

**Текст закрытия:** «Проверили отриц. ТН в накладной, попробуйте провести. Если ошибка повторится — обратитесь в отдел ценообразования.»

**Связь с классификацией:** «Расценка ниже себестоимости».

### 2. Цены не подтягиваются при внутреннем перемещении

**Область:** только перемещение **магазин ↔ магазин** (покупатель ↔ поставщик). **[KB id=789](https://support.willesden.by/front/knowbaseitem.form.php?id=789)**.

**Как должно работать:**
1. **Магазин-покупатель** создаёт заказ на закупку у магазина-поставщика.
2. После проведения — автоматически **порождённый заказ продажи** с тем же номером, что у заказа «Закупка».
3. **Магазин-поставщик** создаёт накладную продажи **по порождённому заказу** (не вручную!), проводит (приход + списание с остатков).
4. **Магазин-покупатель** создаёт накладную закупки с тем же автоматическим номером и проводит.

**Типичная ошибка:** заказ инициирует **продавец** → тип «Заказ(польз.) (продажа)», номер заказа неверный, цены не подтягиваются. Должен инициировать **покупатель** → тип **«Заказ на основе заказа»**.

**Исправление:**
1. Удалить ручной заказ, созданный поставщиком.
2. Найти заказ с номером, созданный **покупателем**.
3. На его основе создать новый заказ.

**Связь с классификацией:** «Цены не подтягиваются во внутреннем перемещении».

### 9–10. Акты списания и уценки: открытие / удаление

**Куда:** «**Склад**» → «**Списания**» (нужен **номер акта**). **Категория:** ПО → LS Fusion.

**Обязательно:** **письмо сектора охраны ТО** на открытие / правку / удаление.

#### Удаление

| Тип акта | Согласования |
|---|---|
| Любой акт **списания** или **уценки** | **СБ** + письмо охраны ТО |
| **Проведённый** акт **списания** | **СБ + бухгалтер** + письмо охраны ТО |

#### Открытие на редактирование

| Состояние | Действия | Ответ пользователю |
|---|---|---|
| **1.** Не проведён, **не закрыт** | Дата → **текущая**; статус → **«Создан»** | «Акт открыт для редактирования.» |
| **2.** Не проведён, **закрыт** | Акт датой **не позднее 5–7 дней** → дата **текущая** + статус **«Создан»** | «Акт открыт для редактирования.» |
| **3.** **Проведён**, не закрыт | Снять **«Проведён»**; дата → **текущая**; статус → **«Создан»** | «Акт списания открыли. После внесённых корректировок его необходимо **повторно отправить на согласование**.» |
| **4.** **Проведён и закрыт** | Не открывать самостоятельно | «**Обратитесь к вашему бухгалтеру** с просьбой открыть акт; после чего откроем документ для редактирования.» |

**Дополнительно (legacy / СЭД):**
- Статус **«Отправлен»** — акт в **СЭД**; до отправки редактирование доступно; сменить на «**Создан**» + дату.
- Статус **«Создан»** — редактирование **5 дней** с создания; если срок вышел — сдвинуть **дату создания** на более позднюю (в пределах нескольких дней).
- **Проведённый** акт (текущий месяц): снять «Проведён», дата не более **5 дней назад**, статус «Создан».
- **БВД** — согласование через **СЭД**; **БМК** — через **личную почту**.

**После любых правок** → акт **повторно на согласование**.

**Связь с классификацией:** «Открыть акт списания на правку», «Уценку нельзя редактировать».

### 13. Цена в накладной не совпадает с ценой в заказе

**Сектор:** **СРИСиС** | **Категория:** ПО → LS Fusion

**Признаки:** цена в накладной отличается от цены в заказе на закупку.

**Как узнать, что заказ — автозаказ:**

2. Вкладка **«По документу»** (внизу экрана) → столбец **«Имя пользователя»** = **«системный пользователь»**.

### 21. Ошибка при заполнении атрибутов возвратной ЭТТН (invalid value «с» for «MM»)

**Сектор:** **СРИСиС** | **Категория:** ПО → LS Fusion

**Когда возникает:** при **сохранении** формы **«Атрибуты накладной»** **возвратной ЭТТН** в LS Fusion.

**Текст ошибки (пример):**
- `Внутренняя ошибка сервера: … ERROR: invalid value "с" for "MM"`
- `Подробности: Value must be an integer.`

**Правило разбора:** если в тексте **`invalid value «с» for «MM»`** и **`Value must be an integer`** — в **100% случаев** причина в поле **«По доверенности (номер, дата)»**. **Администратору сервера и PostgreSQL заявка не нужна.**

**Почему:** система разбирает **дату доверенности** в числовом формате месяца **MM**. Если месяц написан **словами** («сентября» и т. п.), парсер берёт первую букву **«с»** вместо номера месяца.

| Вариант | Пример поля «По доверенности (номер, дата)» |
|---|---|
| **Неправильно** | `№4618 от 08 сентября 2026г.` — месяц словами |
| **Правильно** | `№4618 от 08.09.2026` — **DD.MM.YYYY** |

**Шаги:**
1. В окне «Внутренняя ошибка сервера» — **«Закрыть»**. Форма «Атрибуты накладной» остаётся открытой.
2. Блок **«Отпуск»** → поле **«По доверенности (номер, дата)»**.
3. Месяц **словами** заменить на **числовой формат DD.MM.YYYY** (номер доверенности можно оставить).
4. **«Сохранить»** / **«ОК»**.

**Текст ответа по заявке (дословно):** *«Добрый день. Указывайте дату доверенности в числовом формате DD/MM/YYYY»*

**Инструкция (файл):** `M:\Документы\Инструкции\Мои инструкции\LS Fusion\Ошибка при заполнении атрибутов возвратной ЭТТН.docx`

**БЗ:** [KB id=834](https://support.willesden.by/front/knowbaseitem.form.php?id=834)

### 4. Проверка / регистрация GTIN

**Обязательно в заявке:** **ШК товара**.

**Алгоритм:**
1. Fusion → карточка товара → признак **«GTIN зарегистрирован»** установлен → **OK**, работа продолжается.
2. Не установлен → справочник **epass** → параметр **«зарегистрирован gtin»** подтверждает проверку.
3. GTIN **не зарегистрирован** или **нет в столбце GTIN**:
   - обращающийся → **категорийный менеджер / КУ** (форма на регистрацию GTIN);
   - затем **НСИ** → подача в **epass** → GTIN в карточку.
4. **Нет GTIN, есть только ШК** → сначала **КУ**, **не сразу НСИ**.

**Правила:**
- **Штучный:** GTIN = ШК *(исключение — несколько ШК у одного товара)*.
- **Весовой:** GTIN присваивает **epass**.

**Закрытие:** «GTIN зарегистрирован.» / «GTIN не зарегистрирован — обратитесь к категорийному менеджеру.»

**Связь с классификацией:** «Проверить / зарегистрировать GTIN».

### 5. Неверное наименование на ценнике / в оборудовании

**Суть:** на ценник подтягивается поле **«Наименование»** (под строкой **«Штрихкод»**), **не** «Наименование для оборудования».

**Шаги НСИ:**
1. Найти карточку по **ШК**.
2. Исправить поле **«Наименование»**.
3. Сообщить пользователю: **прогрузить пик-лист на кассе** (**САКПО**).

**Связь с классификацией:** «Неверное наименование для оборудования».

### 6. Трансляция карточек БВД → БМК

**Только направление БВД → БМК** (обратно **невозможно**).

**Шаги:**
1. Определить тип ШК: **штучные** — длинные (8, 12, 13, 14 цифр); **весовые** — короткие (5 цифр).
2. Проверить наличие и наименование в базе **БМК**; у каждого товара — **короткий ШК БМК** (может быть несколько ШК: старые карточки, ассортимент).
3. ШК из БВД **есть** в БМК, наименования **разные**, но **один товар** → выбрать товары → **«Действия»** → **«Отправить JSON»**.
4. Короткий ШК совпал, **наименования карточек разные** (разные товары) → **трансляция невозможна**.

### 7. Не применяется скидка по карте «Хамелеон»

**Сектор:** **САКПО** | **Set10 (SetCentrum)** + **LS Fusion** (прогрузка **цены 3** в оборудование)

**Признаки:** на кассе **не применяется скидка по карте Хамелеон** на **конкретный товар** (обычная цена есть, цена для держателя карты — нет).

**Не путать:**
- **Привязка / блокировка** карты «Хамелеон» / «Асобая» → **отдел маркетинга** (не САКПО).
- **Ценник «Хамелеон» без прайса** в LSF → **САиСПС / СРИСиС**.
- **Массовая** прогрузка скидок **по ТО** из офиса → **СРИСиС** (не этот сценарий).

**Обязательно из заявки:** **номер торгового объекта (магазин)**; **штрихкод** или **точное наименование** товара.

**Типичная причина (≈95%):** на кассе есть **цена 1** (обычная розничная), но **нет цены 3** (для держателя карты Хамелеон) — нужна **прогрузка товара в оборудование**.

| Тип цены | Значение |
|---|---|
| **Цена 1** | Обычная розничная цена для покупателя **без** карты Хамелеон |
| **Цена 3** | Цена для покупателя **с картой Хамелеон**. Если её нет в Set10 на магазине — скидка **не применится** |

#### Диагностика в Set10

1. Открыть **Set10 (SetCentrum):** http://172.16.0.85:8090/
2. **«Товары»** → **«Поиск товаров»** → ввести **наименование** или **штрихкод** из заявки → открыть **карточку**.
3. Вкладка **«Политика продаж»** → справа над таблицей цен — синяя ссылка **«ВЫБРАТЬ»** → отметить **магазин из заявки** → подтвердить. В шапке: **«Выбрано магазинов: 1»**.
4. В таблице политики продаж — строка **магазина из заявки**, колонка **типа цены**:
   - **только «Цена 1»** → **цены 3 нет**, нужна прогрузка в оборудование;
   - **«Цена 1» и «Цена 3»** → цена для карты уже в Set10; проблема **не в отсутствии прогрузки** (проверить **срок действия** цены 3; при необходимости **повторно выгрузить** в кассы).

#### Прогрузка товара в оборудование (LS Fusion)

**Если цены 3 нет:**

1. **LS Fusion** → форма **«Обновление розничных цен»**.
2. Поле **«Наименование»** — **магазин из заявки**.
3. Поле **«Штрихкод»** — **ШК товара** → найти позицию.
4. В строке товара — галочка в колонке **«Отм.»**.
5. Внизу — **«Загрузить в оборудование (с товарами)»**.
6. Дождаться завершения загрузки.

**Проверка, что в кассы ушла цена 3:**

1. Верхняя панель Fusion → **«Оборудование»** → вкладка **«Загрузки прайса в оборудование»**.
2. Поле **«Наименование»** — тот же **магазин**.
3. Найти **свежую** строку загрузки в кассы (класс **«Загрузка прайса в кассы»**).
4. Нижняя панель → вкладка **«Штрихкод»** — нужный товар в списке.
5. Колонка **«Дополнительное поле»**: атрибут **`number 3`** / **`ftNumber`: 3** — это **цена 3**.
6. Если **`ftNumber` 3** нет — цена для карты Хамелеон **не ушла** в кассы: повторить загрузку, проверить карточку товара в Fusion.

#### Проверка результата в Set10

1. Вернуться в **Set10** → та же карточка → **«Политика продаж»** → магазин **выбран**.
2. В фильтре типов цен — **«Цена 1»** и **«Цена 3»**.
3. В таблице — строка **«Цена 3»** (обычно **ниже** цены 1) со **сроком действия**.
4. После появления **цены 3** скидка по карте Хамелеон применяется на **всех кассах** магазина.

**Краткий алгоритм:** заявка (ТО + ШК) → Set10: политика продаж, только цена 1? → Fusion: «Обновление розничных цен» → загрузка → журнал: `ftNumber` 3 → Set10: появилась цена 3.

**Закрытие:** «Товар прогружен в оборудование, в Set10 появилась цена 3 для карты Хамелеон. Проверьте пробитие на кассе.»

**Инструкция (файл):** `M:\Документы\Инструкции\Мои инструкции\Set10\Не применяется скидка по карте Хамелеон.docx`

**БЗ:** [KB id=832](https://support.willesden.by/front/knowbaseitem.form.php?id=832)

**СЗТ / соц. значимый товар** (**цена 2**, не цена 3) — см. **СРИСиС п. 17a**; [550828](https://support.willesden.by/front/ticket.form.php?id=550828).

**Связь:** точечная прогрузка — также каталог **СРИСиС п. 17**.

### 8. ТСД (Palm): «Маркировка» — «Валидация марки»

| Сканер **не считывает** код (любые операции) | **СОКС** |
| **«Валидация марки»** / ошибка сервера в сценарии **маркировки** на ТСД | **САКПО** |

**Контекст (информационно):** у оператора **А1** предоставляется сервис проверки маркировки **молочной продукции**; на ТСД ошибки **500** при скане могут быть связаны с этим сервисом — первичный разбор и маршрутизация в УИТ через **САКПО**, не через **СОКС** и не **НСИ**.

**Обязательно в заявке:** **номер ТО**, **телефон** ([KB id=278](https://support.willesden.by/front/knowbaseitem.form.php?id=278)); **скриншот** окна ошибки; **ШК** и/или **наименование** товара; **база** (БВД / БМК); по возможности — документ/операция на ТСД (приёмка, маркировка).

**Шаги САКПО (ориентир):**
1. Воспроизвести на ТСД: сеть, время, та же позиция и код маркировки.
2. Проверить настройки сценария маркировки на ТСД и актуальность данных по товару; при расхождении карточки — согласование с **НСИ** (не назначать **НСИ** первично без разбора САКПО).
3. При **500 / Internal Server Error** — проверка по регламенту САКПО (в т. ч. доступность сервиса **А1** для молочной маркировки); при массовом сбое — зафиксировать ТО и время.
4. Если ошибка **только на одном** ТСД и другие коды читаются — рассмотреть **СОКС** (аппарат); если ошибка **только на маркировке** на нескольких ТСД — оставить **САКПО**.

**Пример:** [551147](https://support.willesden.by/front/ticket.form.php?id=551147) — «Валидация марки», молочный товар, `Internal Server Error`.

**Закрытие:** по итогу разбора («маркировка проходит», «временный сбой сервиса — повторите позже», «настройки/данные исправлены»).
